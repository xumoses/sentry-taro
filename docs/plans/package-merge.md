# 统一包合并方案

状态：整体方案已确认。本文作为实施前基线；提交此文档时，尚未开始代码合并、包发布或应用迁移。

## 已明确的方向

- 将 `xumoses-sentry-miniapp` 与 `sentry-miniapp-replay-taro` 合并到 `sentry-taro`。
- 后续对外只发布一个 npm 包：`@xumoses/sentry-taro`。
- 目标使用场景为 Taro 4.2.x + React 的小程序应用。
- 以首个验证项目完成首次迁移与验收；公开仓库不记录企业项目身份。
- 第一阶段在功能一致的前提下完成合并发布，允许简单优化，暂缓复杂重构。
- 第二阶段进行重构优化，主要目标之一是公共 API 尽量对齐官方 Sentry SDK。

## 已确认的边界

- 保留既有平台能力；第一阶段正式验收覆盖 Taro 4.2.x + React 18 + 微信小程序，以 iOS 为准。Android 验收后续补充；记录实际验证的微信基础库版本，暂不承诺未经验证的最低版本。
- 错误监控可独立使用，Replay 显式开启；保持现有采样、隐私及上传行为。
- 第一阶段完成须覆盖自动化与产物检查、首个验证项目的开发者工具验证、真实 Sentry 错误接收和 Replay 播放、npm 发布、项目迁移及 CI、体验版真机验证，各门槛分别留证。企业相关验收证据留在非公开环境。
- 旧包不再修复，所有修复只进入新包；首个验证项目迁移验收通过后，旧包 deprecate 并指向新包。
- 允许完成合并必需的工具链、内部引用、重复类型和应用接入脚本调整。不升级 Sentry 核心；除明确的缺陷修复和必要兼容调整外，不重设计录制、采样、遮罩、压缩及投递策略。
- 将依赖外部 SDK 源码路径才执行的真实契约测试改为新仓库必跑测试。
- 公开示例定位为供潜在使用者参考的轻量接入 demo，展示基本接入方式，不承担第一阶段验收职责，也不要求建立示例验证流程。使用量增加后再加强示例与验证能力。
- 缺陷通过“提取触发条件 → 合成最小复现 → Vitest 回归”的方式进入公开仓库。公开测试保留通用问题描述与修复依据，原始证据及内部来源对应关系留在非公开环境。具体规则见[公开回归测试方案](./public-regression-testing.md)。
- 旧包已有问题中，简单修复进入第一阶段；复杂且非阻断的问题保留最小复现并明确登记为待修复，不计为通过。隐私泄漏、构建失败、核心上报或播放失效必须修复。

## 公开信息边界

本项目是开源项目。文档、示例、测试 fixture、截图、构建产物及 npm 发布内容不得包含企业内部项目名称、路径、仓库、提交、域名、部署身份、CI 标识、Sentry 事件或 Replay 标识，以及企业应用源码和 sourcemap 等内部材料。

公开缺陷应描述 SDK 的通用输入、预期行为、实际行为、影响范围和使用合成数据的最小复现。只有已确认属于 SDK 或公共接入能力的问题才记录为 SDK 缺陷；未定位的集成问题不得归因于 SDK。企业相关调查与原始验收证据留在相应非公开环境，不复制到本仓库。

公开验收清单使用匿名的“首个验证项目”与通用场景；企业具体实现不作为开源用户的接入要求。

## 源仓库核查事实（2026-10-14）

- 合并基线为 SDK 提交 `728b008`（`1.13.1-beta.7`）和 Replay 提交 `5ff1a19`（`0.1.0-beta.6`）。采用经过检查的代码快照导入，不合并旧 Git 历史。
- 现有 Replay 提供 `/react/root`、`/taro/lifecycle` 轻量入口及独立 `/worker` 产物，迁移需保持单一 SDK/client/coordinator 和产物兼容。
- SDK 已直接导出大量 `@sentry/core` 公共 API；Replay 已使用 `replaysSessionSampleRate`、`replaysOnErrorSampleRate`，但仍通过显式 `sdk` 参数及自有 bridge 接入。
- 两个包均基于 `@sentry/core@10.66.0`；第一阶段保持此基线。

## 已确认的 API 分期

以官方 JavaScript SDK `10.66.0` 的通用 API 和 React/Replay 公共接口为参考，小程序平台能力单独说明。

- 第一阶段：可做薄封装、统一导出和低风险调用简化。例如无需调用方显式传入同包 SDK，并提供 `replayIntegration` 入口；保留必要兼容入口与轻量子路径。
- 第一阶段：仅在语义一致时采用官方名称；名称相同但启动、停止、缓冲或投递语义不同的 API 不宣称兼容。
- 第二阶段：处理 Replay 控制方法、配置结构、生命周期及 React 接入等需要行为调整的系统性对齐。
- 发布前区分“已对齐”“小程序扩展”“暂未支持”，避免只改名称而形成兼容承诺。

参考：[官方 Replay 10.66.0 实现](https://github.com/getsentry/sentry-javascript/blob/10.66.0/packages/replay-internal/src/integration.ts)、[官方 Replay 接入示例](https://sentry.io/quickstart/session-replay/)。

## 发布与迁移

- 首版为 `0.1.0-beta.1`，使用 npm `beta` 标签；第二阶段 API 收敛后再发布稳定版。
- beta 期间允许必要的破坏性调整，须附迁移说明；阶段一不承诺所有临时接口长期稳定。
- 迁移前在非公开环境保存验证项目原依赖、锁文件和接入状态，失败时可恢复；恢复旧版本不代表旧包继续接受修复。
- 每次验证绑定具体包版本和构建产物，不将源码测试、tarball 检查、CI、真实接收和设备验收混为一项结果。

## 工具链分期

最终技术栈为 pnpm、Vite、Vitest、Oxlint、Oxfmt。用户已接受第一阶段暂时保留 Jest 与 Vitest，并授权根据迁移成本决定完成阶段。

- 第一阶段统一 pnpm、锁文件及根运行命令；保留 SDK 的 Jest/TS5 构建测试环境，以及 Replay 的 Vite+/Vitest 环境。必要时用不发布的内部工作区隔离工具依赖，始终仅发布一个 npm 包。
- 第一阶段保留现有构建器配置和语法目标；处理多个构建的输出清理与组合，验证核心不重复、轻量入口与 Worker 仍独立。统一包管理器不顺带升级所有构建器。
- 新增脱敏回归使用 Vitest；真实 recorder/core 契约测试必跑。
- 第二阶段迁移剩余 Jest 测试到 Vitest，完成独立 Vite/Vitest、Oxlint、Oxfmt 和 TypeScript 配置统一，保留测试覆盖与行为。
- 开发工具所需 Node 版本与消费者安装环境要求分别声明；具体工具版本在实施时按兼容性固定，不通过抬高消费者要求掩盖开发工具冲突。

## 第一阶段执行顺序

1. 核对固定源码基线及工作区状态，检查将迁入的源码、配置、测试和文档，整理来源与第三方通知。仅导入所需代码快照，不导入旧历史或内部材料。
2. 建立单一发布包、pnpm 锁文件和统一命令；保留必要的内部工具隔离，迁入现有测试，记录测试范围及已知非阻断问题。
3. 合并 SDK 与 Replay 内部引用、重复类型和构建产物，保持单一运行时及轻量入口、独立 Worker。完成简单 API 对齐、包身份更新、迁移说明与轻量 demo。
4. 运行既有测试与必跑契约测试；将新增缺陷转为合成 Vitest 回归并处理阻断问题。检查 tarball 安装、导出与类型、产物语法、许可、内容边界及体积变化。
5. 在非公开环境使用候选 tarball 接入首个验证项目，调整依赖、构建及 Worker 接入，完成开发者工具与真实 Sentry 接收、关联及 Playback 验证。实际项目的精确基线与证据在该环境记录。
6. 发布 `0.1.0-beta.1` 到 npm `beta`，再使用真实发布版本完成项目迁移、CI 与 iOS 体验版真机验收。候选包成功不能替代发布包验收；如需修复，递增 beta 并重新验证受影响范围。
7. 首个项目验收通过后，旧包 deprecate 并指向新包；公开仓库仅记录不含内部身份信息的范围说明及可复现测试。

第一阶段完成要求上述合并发布和真实项目验收闭环。Android、示例验证体系及复杂 API/工具链重构均不作为本阶段完成条件。

## 第二阶段完成方向

- 系统性对齐官方 Sentry API 的命名、配置及可实现的行为语义，明确小程序平台差异，并提供迁移说明。
- 完成 Vite、Vitest、Oxlint、Oxfmt 与 TypeScript 配置统一，保持已有回归覆盖。
- 在 API 收敛、相关行为和产物验证通过后发布稳定版。
- Android 验证后续补充；示例验证能力随使用量增长加强，二者不与每项重构强制绑定。
