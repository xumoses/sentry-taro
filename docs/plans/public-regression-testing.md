# 公开回归测试方案

状态：合成复现与 Vitest 回归方式已确认。第一阶段由自动化测试、产物检查与首个验证项目的本地接入及真实服务验收共同验证；公开示例仅用于接入展示，不承担验收职责。

2026-10-14 补充决策：第一阶段通过本地候选 tarball、微信开发者工具、真实 Sentry 接收、Replay 关联与 Playback 完成集成验收，不要求公网 npm 发布。正式发布、依赖锁文件切换、发布包 CI 及旧包弃用移至第二阶段发布工作。真机验证在第二阶段重构完成后进行，以 iOS 为准，Android 后续补充。

## 缺陷转为测试的方式

从问题中提取触发条件，重新构造最小合成输入。复现应保留导致缺陷的结构、顺序、边界值或竞态条件，不保留原始业务记录。

例如系统信息解析缺陷可用人工构造的系统字符串覆盖带架构后缀的输入；页面切换问题可用 `PageA`、`PageB` 与受控时钟模拟 detach/attach 的事件顺序；源码定位问题只使用自建的微型源码和对应生成的 sourcemap。示例仅说明转换方法，不代表这些问题已确认属于 SDK 或已纳入修复范围。

不得将原始错误事件、录制、截图或业务 sourcemap 复制后，仅替换项目名、域名或账户字段就作为公开 fixture。数据内容、节点结构、源码片段、业务文案和绝对路径也可能保留内部信息。

每个案例记录通用缺陷描述、最小触发条件、预期行为、合成输入构造方法和断言依据。内部来源对应关系仅保留在原非公开环境中；公开测试名称和注释不包含内部工单或事件标识。

## 验证层次

| 层次                               | 建议覆盖                                                                              | 可证明的结论                                                            |
| ---------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Vitest 自动化                      | 错误归一化、合成录制的遮罩、节点增量、页面生命周期、错误关联、Worker 压缩与回退       | 给定输入与事件顺序下，SDK 行为和输出满足断言                            |
| 本地产物契约                       | 从 npm tarball 安装、公共导出与类型、独立 Worker、轻量入口依赖、envelope 序列化及解码 | 发布产物可消费，数据结构和构建边界符合约定                              |
| 首个验证项目的开发者工具验证       | 项目启动、错误触发、Replay 开关、合成输入遮罩、页面切换、Worker 状态                  | SDK 在该小程序环境中可运行，对应本地流程通过；证据留在非公开环境        |
| 首个验证项目的第一阶段真实集成验收 | 本地候选 tarball 的实际 Sentry 接收、Replay 关联与 Playback                           | 对应候选包与服务上的集成结果；证据留在非公开环境                        |
| 第二阶段发布包验收                 | 正式发布版本的依赖与锁文件迁移、发布包 CI                                             | 对应实际发布版本及构建环境的集成结果；本地候选包不能代替                |
| 第二阶段完成后的真机验收           | iOS 体验版运行、上报、关联与播放，Android 后续补充                                    | 对应设备与基础库版本上的集成结果；不能由开发者工具或内存 transport 代替 |

自动化契约测试使用本地可观测的测试 transport 或等价收集接口，不发送外部网络请求。收集真实 SDK 生成的 envelope/录制并验证结构，不用预先写好的成功响应代替捕获与序列化过程。若自建 transport 绕开实际请求实现，请求实现必须有独立契约测试，且本地结论不扩大到真实网络投递。

公开示例是轻量接入 demo，使用合成数据展示初始化和 Replay 接入方式。第一阶段不建立示例自动化或手工验收流程；后续随使用量增长再加强。不将示例作为实际 Sentry Playback 或真机验证的证据。

## 已核实的复用基础

两个源仓库已有合成节点、录制和运行时 fixture，真实 core 加内存 transport 的测试，以及 Worker 压缩与回退验证。SDK 支持自定义 transport；测试可用虚构 DSN 启用 SDK，再通过内存 transport 收集真实生成的 envelope，不发出网络请求。默认请求与离线队列需用独立的请求和存储 mock 测试。

现有 SDK 的 Taro 示例已使用开发者工具测试 AppID 配置；Replay 的示例是可参考的页面片段。demo 可复用这些公开材料并更新依赖和接入写法，具体展示形态以简单易懂为准。现有 viewer 只显示录制摘要、事件和 JSON，不具备实际回放渲染能力。本轮仅核查源码，没有运行新示例。

## 回归有效性

- 已修复问题应证明：同一案例在未修复实现失败，在修复实现通过；不能只断言当前实现的输出。
- 简单修复进入第一阶段；复杂且非阻断的问题保留最小复现并明确标为待修复。隐私泄漏、构建失败、核心上报或播放失效必须修复。
- 第一阶段未修复的已知问题必须显式登记其状态，不能把 skip、空断言或未执行的契约测试计为通过。
- 测试不依赖内部源码、绝对路径、网络账号或服务凭据，CI 可独立运行。
- 测试 fixture 优先由小型工厂生成，字段按需要列出；时间、随机值及 ID 可复现。
- 发布前检查源码、测试、文档和 tarball 的内容边界，检查日志只报告位置和类型，不回显疑似敏感值。扫描是辅助措施，不能替代合成复现设计。
